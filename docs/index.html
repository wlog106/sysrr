03 · record side
Recording one syscall

    
What the kernel reads is copied at entry. What it writes is copied at exit. Then one fixed-size record commits the call.

  

    

    

    
    

    

    

  


  

    
Is anything missing?
Every syscall takes the next seq, so holes are visible. Each SYSCALL record says how many DATA records it expects.

05 · restore
Attach: the copy installs its own filter

    
A process can only install a seccomp filter on itself, and a restored process never calls execve. So sysrr_replay borrows its instruction pointer for a few milliseconds.

    09 · signals
    Signals: replayed or happen again?
    
    
    Only signals the copy cannot produce by itself come from the log. Click one to follow its path.
    
  
    
    
    
    
    
    
    
    Where a logged signal lands: at the thread's last syscall before it. One that arrived mid-computation comes back slightly early, because exact placement would need a CPU branch counter, which the test VMs lack. Measured: 71 of 71 timer signals, 8 of 8 outside signals at the right syscall.

    12 · honest edges
    Limits
    
    
    The log only sees what crosses the kernel boundary. Everything here follows from that, or from CRIU.
    
  
    
    
    invisiblevDSO, rdtsc, io_uringNo syscall, no record. The acpi_pm clock source forces clock reads through the kernel; glibc's getrandom across machines still diverges, honestly.
    
    
    threadsRaces inside user codeLocks taken nanoseconds apart can't always be ordered. -T plus the search fixes most; 18 of 20 cross-machine rounds passed.
    
    
    threadsPython's GILHanded over on a 5 ms timer in user space. Python threads replay a few dozen calls, then diverge honestly.
    
    
    signalsMid-computation signalsDelivered at the previous syscall, slightly early. Exact placement needs a CPU branch counter (no PMU on the test VMs).
    
    
    signalsSIGCHLD timingComes from the real children at their own time, so shell scripts that depend on it end in an honest divergence.
    
    
    checkpointOpen TCP connectionsNeed --tcp-established on both checkpoint and restore; podman then keeps the original name.
    
    
    checkpointvfork before execA checkpoint can catch Python's subprocess mid-vfork and fail after 10 s. Checkpoint again; replay that attempt's generation.
    
    
    live modeStand-ins and no second checkpointConnections from the recording stay stand-ins; CRIU can't checkpoint a process that has a seccomp listener.
